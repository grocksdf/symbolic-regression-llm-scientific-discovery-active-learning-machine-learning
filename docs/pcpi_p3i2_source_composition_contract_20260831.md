# PCPI P3I.2 decision-targeted runner source-composition contract

## Scope

P3I.2 composes the response-free P3I.1 repair into the historical measured-pool
runner. It is still a correctness phase. The candidate protocol is deliberately
marked `operational_execution_authorized=false`, and the shared runner checks
that authorization before testing the data path or creating an output
directory. Therefore this phase cannot become an accidental real experiment.

P3H.9 remains immutable negative development evidence. P3I.2 does not rerun,
reinterpret or overwrite it, and it does not claim that the new policy is
effective.

## One coherent C1--C3 path

Under the P3I protocol flag, every matched policy is evaluated with the same
initial-frozen operational partition constructed by
`aggregate_decision_equivalent_classes`. The partition uses the posterior mean
Bayes action under squared loss, one common H0 posterior-mixture scale, the
registered action domain and the unchanged budget-derived threshold. Its
quantile coordinate list is empty by construction; the historical Student-t
predictive-quantile class path remains available only to historical protocols.

The P3I PCPI branch dispatches directly to
`score_decision_targeted_actions` before either historical joint scorer. The
scorer receives the exact model-specific likelihood-power posterior family and
the matching prequential residual family from the operational P3H lifecycle.
Its primary utility is

`min_eta I_eta(C; Y_a)`.

The P3H residual-law correction is represented by the registered common
invertible PIT transport. Mutual information is invariant under that transport.
Conditional Gaussian-moment EPIG is exactly zero and cannot re-enter through a
reporting alias, fallback or assessment rule. The covariate-only representative
safe set remains a feasibility constraint. An empty safe set is a terminal
failure, not a change of utility.

## Auditable reporting and assessment

Every P3I query records the operational-class metric and common-scale hash,
transport method, information-invariance flag, decision target, class-EIG,
zero conditional EPIG, robust per-model scores, numerical intervals,
representative-safe decision and before/after residual-family hashes. The
protocol Gate requires these identities on every PCPI query.

The primary assessment is frozen-class log-risk reduction. Strong P3I evidence
would require a positive paired frozen-class entropy-gain confidence bound
versus random in every registered dataset family, controlled class-gain
negative transfer, nondegenerate class aggregation and a fully valid decision
rule. Validation RMSE/NLL remain reported as secondary scientific limitations;
they are not combined with the primary class-risk decision after results are
seen.

## Immediate failure visibility

The P3I candidate protocol changes the historical `record-all` execution policy
to `fail_fast_record_terminal_no_seed_replacement`. The first policy or dataset
failure is appended to the fsync-backed progress log, written once to
`TERMINAL_FAILURE.json`, and raised immediately. The terminal record forbids
reuse of the same output directory, retry and seed replacement. It contains no
candidate response or held-out value. A process-level kill can still interrupt
between events, but every completed progress event is crash-durable.

## Correctness result and authorization boundary

The P3I.2 source Gate passes all eight registered decisions. The focused P3I,
P3H and source-integrity regression passes all 50 tests. The complete repository
regression passes `749/749` with final exit code zero, and `git diff --check`
passes. No historical failure or assertion was masked or relaxed. The Gate uses
no simulated experiment, real data, validation response, candidate response or
held-out value.

Operational execution, efficacy evidence and paper claims remain blocked. A
later phase must freeze a new execution-authorized schema, exact source/tree,
configuration hash, monitoring command and unique output identity. Only then
may the user receive one real-development command.
