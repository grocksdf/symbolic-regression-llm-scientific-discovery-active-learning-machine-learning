# PCPI P3I.4 shared-H0 real-development protocol

## Purpose and boundary

P3I.4 is the root repair for the immutable P3I.3 protocol failure. It does not
reinterpret or replace that result. It changes no empirical threshold or
acquisition objective. After removing `schema`, `stage` and the new explicit
`p3i_initial_frozen_target_source`, the P3I.3 and P3I.4 configs are identical.

P3I.4 is one user-only, held-out-closed, failure-informed development run. It
is not independent confirmation. Codex may execute source, algebra, parser,
environment and no-data preflight checks only.

## Shared H0 construction

For each registered dataset and seed, the runner first freezes all matched
initial, validation and candidate subset commitments and the warmup-only
standardizer and design preconditioner. It then computes one eta-one conjugate
posterior from the complete 32 already-open initial observations using batch
sufficient statistics. The registered decision-regret classes and their common
H0 mixture scale are constructed once from this canonical posterior and the
registered candidate action domain, before the policy loop.

The resulting typed `FrozenInitialClassTarget` contains the canonical
posterior, operational classes, structure-to-class partition, posterior target
hash and frozen source identity. Every policy receives the exact same object.
P3I.4 fails closed if the object is missing, internally inconsistent or belongs
to another posterior target.

PCPI separately reconstructs the four P3H likelihood-power states from the
unchanged 16/16 chronological roles. This path is necessary to form leakage-safe
strict-prefix raw PIT histories and is not replaced by a batch residual fit.
Before scoring, the eta-one prequential conjugate sufficient statistics must
agree with the shared batch target under an a-priori floating accumulation
bound proportional only to the number of opened observations. A material state,
prior, structure, likelihood-power or history mismatch is terminal. The class
identity itself is never rounded or approximately compared.

## Unchanged acquisition and assessment

All three datasets, eight seeds, four policies, initial/acquisition/candidate/
validation budgets, complete likelihood-power family, representative-safe
constraint, target-only robust class-EIG, interval-frontier resolution,
quadrature schedule, class threshold, failure policy, paired assessment and
tie breaks remain unchanged from P3I.3. Conditional predictive EPIG remains
exactly zero. Candidate responses are revealed only after selection,
validation is evaluation-only and held-out remains sealed.

Protocol success requires all 96 runs and 3072 queries, no execution failures,
one shared initial partition hash per dataset/seed, the exact registered shared
target source on every run, a valid P3H hash chain for every PCPI run, a valid
evidence registry, exact source/config/runtime identities and held-out closure.
An efficacy-negative but protocol-valid result remains valid negative
development evidence.

`b7bf88a64dd375e25c7d679de129c654c3346462215ffa24c425c762fb8bc4a6`,
and the historical base executable, DLL and `pyvenv.cfg` identities remain
enforced by the existing runtime integrity tests. Before checking the data
directory, the runner additionally requires the virtual-environment launcher
SHA-256
`21bb438c0d4a6f1f164b9a646f6ee000340185e5871180aec06db8d3f07c0082`;
the manifest records the observed launcher hash. A Codex sandbox denial when
launching the external base executable is not a runtime change and must not
trigger installation or use of an alternative formal runtime.

The ASCII-only Windows PowerShell 5.1 supervisor freezes branch, commit, tree,
config hash, Python executable hash, clean source and unique output. It isolates/restores historical
untracked evidence, displays fsync progress, preserves stdout/stderr and stops
the child on interruption. To avoid the demonstrated PowerShell 5.1 null
exit-code behavior, it starts an encoded child PowerShell that performs file
redirection internally; the monitored process itself is not launched with
`Start-Process -RedirectStandardOutput/-RedirectStandardError`. Null or nonzero
exit codes fail closed and report the actual integer when present.

The no-data `-PreflightOnly` route creates no experiment output and opens no
data. The real route is user-only and must use a new unique output/stash pair.
