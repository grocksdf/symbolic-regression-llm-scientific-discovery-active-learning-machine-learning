## Root correctness defect

`SequentialReferencePosterior.fit_batch()` constructed each structure design
with the frozen termwise center/scale preconditioner. In contrast,
`predictive_components_for_partition()` and
`posterior_epistemic_variance()` rebuilt raw polynomial basis rows directly.
The resulting coefficient vector was learned in preconditioned coordinates but
multiplied by raw coordinates for posterior means, predictive variances,
validation RMSE, uncertainty, QBC, class EIG, and the PCPI fallback. The
predictive NLL path called the posterior engine and therefore used the correct
coordinates, so RMSE and NLL were not even generated by one predictive object.

This defect was not detected by the P3B.5 tests: they checked posterior
probability invariance and term standardization, but did not compare each
preconditioned predictive component with the posterior engine's own predictive
moments.

## Permitted repair

P3B.6 adds one public posterior design-row route and makes every predictive and
acquisition calculation call it. The posterior, SafeBayes candidates, frozen
budgets, structures, operational-class definition, policies, seeds, splits,
assessment rules, and held-out state are unchanged. New controlled diagnostics
must establish component-moment equality, epistemic-variance equality,
nontrivial-transform sensitivity, and all-policy unit reparameterization
invariance before any new real run.

No dataset name, target name, formula, coefficient direction, result-derived
threshold, held-out record, or acquisition-pool target is used by this repair.
