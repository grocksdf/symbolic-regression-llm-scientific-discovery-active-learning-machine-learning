# PCPI P3K.2 transaction Gate and P3K.3 formal freeze

## Scope

P3K.2 closes the end-to-end correctness boundary after the P3K.1 probability
repair. P3K.3 freezes one real-development comparison. Neither stage changes
the registered datasets, splits, budgets, baselines, seeds, action domain,
ambiguity powers, rank certificate, or assessment rule used by P3J.15. This is
a failure-informed method revision, not independent confirmation.

## Exact stage identity

The reusable transaction implementation retains historical Python function
names, but every durable artifact is selected from the operational state's
frozen lifecycle. A current P3K state therefore publishes only P3K schemas for
the formal query identity, numerical checkpoint, indivisible decision, reveal
receipt, query ledger, run manifest, and terminal policy failure. P3J constants
remain immutable solely to verify historical evidence. Mixed P3J/P3K identities
inside one run manifest fail closed.

Query reporting likewise publishes `p3k_identity_hash`,
`p3k_prior_state_hash`, and `p3k_next_state_hash`; it does not emit a P3J alias.
The shared runner obtains all method-contract keys from the exact frozen
`p3k` prefix and places resumable transaction files under the `p3k` directory.

## Leakage and recovery order

For every PCPI query the enforced order is:

1. bind source tree, configuration, dataset, seed, query index, visible
   candidates, registered target actions, observed representative actions, and
   complete operational state;
2. complete all identity-bound quadrature chunks and publish one decision;
3. open exactly the selected measured-pool response and publish its receipt;
4. advance all four likelihood-power states and publish one state-linked ledger;
5. only then compute validation diagnostics and report the learning curve.

If a durable receipt exists after interruption, recovery reconstructs the same
advance without calling the oracle. Partial quadrature cannot release scores.
A terminal success or failure cannot be resumed in the same output, and seeds
cannot be replaced.

## Frozen P3K.3 experiment

The byte-frozen configuration is
`configs/p3k_3_shared_innovation_real_acquisition.json`. It uses the three
provenance-verified real measurement targets, eight frozen seeds, 32 initial
measurements split into 16 base-warmup and 16 residual-prefix observations, 32
acquisitions, a 128-point measured pool, and 256 validation observations.
Random, uncertainty, and QBC remain on their unchanged matched runner. Only
PCPI uses the P3K transaction and shared-innovation probability law. Held-out
data remains sealed.

The supervisor verifies branch, commit, source tree, configuration bytes, and
Python executable before starting a hidden child process. It streams progress,
preserves separate stdout/stderr logs, exposes the newest numerical checkpoint,
supports only nonterminal resume, and restores the user's untracked evidence
directory. Missing exit codes or terminal artifacts are failures.

P3K.3 can support only its preregistered real-development assessment. A
negative result is preserved. It cannot establish independent confirmation,
universal superiority, open-grammar discovery, a physical intervention, a new
scientific law, or paper acceptance.
